# JEV在本方案中的角色、作用和证据

对应方案：**FMZ-JEV-20260923-R1，候选1623**。本说明以当前代码、冻结参数和实际回测记录为准。

## 角色：新闻事件的风险过滤器

JEV负责把“新消息及已有行情”转成短期价格方向分数。外层程序依据这些分数，决定暂时禁止哪些方向的追加/重开，以及是否关闭已有反向仓位。

| 模块 | 依据 | 控制什么 |
| --- | --- | --- |
| FMZ网格 | 首次开仓锚点、持仓均价、数量层数 | 正常挂单、马丁追加、分侧止盈 |
| EMA趋势控制 | 已完成的120/240分钟EMA与收盘价 | 止盈后是否进入单向状态、是否退出反向仓位 |
| JEV事件过滤 | 新闻标题/摘要和已完成行情 | 消息到来后的短时新增风险限制、条件性反向退出 |
| 硬风控 | 标记价、权益、保证金、名义额和回撤 | 无条件约束订单、止损、强平、账户停机 |

用户提出的“单侧止盈后判断是不是单边行情”，主要落实在EMA趋势模块；JEV提供消息发生时的额外限制。两者与保证金条件都允许时，网格才可以增加相应方向的仓位。

## 模型实际看到了什么

当前使用真实NanoJev开源骨干与另行训练的金融选择头，输入包括：BTCUSDT永续标识、新闻源、标题、摘要、过去5分钟和30分钟收益、已完成行情的波动率，以及当前使用的方向阈值。

模型在三个候选中评分：未来30秒上涨超过阈值、处于阈值区间内、下跌超过阈值。价格阈值定义为：

```text
价格方向阈值 = max(0.03%, 历史30分钟内1分钟收益标准差 × sqrt(0.5))
模型输出 = p_up, p_range, p_down
突破分数 = p_up + p_down
方向偏向 = (p_up - p_down) / (p_up + p_down)
```

“突破”在这里仅指未来30秒收益越过所设价格阈值，不等于已识别出持续单边行情。突破分数0.25也不表示BTC将涨跌25%。概率是模型输出，现有评估未证明其具有可靠金融预测优势。

当前输入**不包含真实持仓数量、浮亏、网格层数或距离强平的余量**。因此，JEV并未直接学会“此刻清仓比继续持有的收益风险更好”；清仓是外层规则对短时价格分数的映射。它也不自行决定网格间距、马丁倍数或杠杆。

## 选中配置的具体动作

本版`jev_action=2`，突破分数阈值0.25，方向偏向阈值0.1，保持180秒。以下规则适用于新消息；若此前已有干预窗口，低分新消息不会提前取消它。

| 新消息评分 | 立即处理 | 干预窗口内 |
| --- | --- | --- |
| 突破分数 < 0.25 | 不新增JEV干预 | 原有趋势、网格及风控继续 |
| 突破分数 ≥ 0.25，且方向偏向绝对值 < 0.1 | 取消双方追加挂单；保留已有仓位与止盈 | 双方暂停追加和重开，持续180秒 |
| 突破分数 ≥ 0.25，且方向偏向 ≥ 0.1 | 有空仓则主动平空，取消空侧追加挂单 | 禁止空侧追加/重开；多侧仍需通过其他条件 |
| 突破分数 ≥ 0.25，且方向偏向 ≤ −0.1 | 有多仓则主动平多，取消多侧追加挂单 | 禁止多侧追加/重开；空侧仍需通过其他条件 |

新的合格消息会把结束时间延长到至少“新消息时刻+180秒”，并用新消息方向更新限制。期限结束只代表JEV限制到期，账户停机、趋势限制、重开等待和保证金要求仍可能阻止开仓。

剩余仓位的止盈和硬风控持续生效。30秒预测范围与180秒干预窗口是两个不同参数；180秒是策略控制选择，不能解释为模型预测了未来3分钟。

### 一个只说明规则的例子

假设收到消息时，多空两边都有仓位，模型输出`p_up=0.30、p_range=0.50、p_down=0.20`。突破分数为0.50，方向偏向为0.20，达到两个阈值。程序会平掉已有空仓，并在180秒内禁止空侧新增风险；多侧是否继续加仓仍由趋势状态、网格价位和预算决定。

若输出变为`p_up=0.16、p_range=0.67、p_down=0.17`，突破分数为0.33，但方向偏向约−0.0303，方向证据不足。此时两侧暂停追加/重开，已有持仓继续接受止盈和硬止损保护。

这些数字是规则演示，不对应某条真实新闻，也不是预期收益示例。

## 双边弃仓模式的关系

程序另有模式1：触发后双边清仓并暂停；模式3：仅暂停追加与重开。用户早期提出的“多空两边全部平掉、暂停网格”对应模式1。本轮选中配置采用模式2，不能把本轮收益写成“JEV双边弃仓策略收益”。模式1候选已参加搜索，但未通过本轮最终两段秒级筛选。

无论哪种模式，JEV都不能撤销保证金、强平或账户回撤停机规则。本项目没有真实下单连接；`guard.py`另提供撤单、双侧退出、确认与暂停的执行意图状态机，具体交易所执行仍待接入。

## 实际做了多少次干预

2026-03-01至2026-09-21，976条可用事件中，主方案触发836次JEV干预，约85.66%。主方案记录：

- JEV方向信号导致实际平仓：**1次**。
- JEV导致双边全平：**0次**，本版没有启用模式1。
- EMA趋势确认导致反向平仓：**30次**。

因此，它在这次回放中的主要用途是消息发生时暂停追加/重开；大部分反向平仓来自趋势控制。836次是信号触发数，不能当成836笔平仓或836次成功躲避风险。`jev_veto_checks`是按方向、按回放步长检查的计数，也不是实际取消的订单数或独立秒数。

回测读取的是事先用真实模型计算的缓存分数；每次回测并不再逐条运行GPU推理。单条真实推理程序为`score_event.py`，金融模型和输入时间的冻结记录另行保留。

## 到底有没有用：需要区分系统作用与模型增量

同一组网格、趋势和风险参数，205天连续100U账户的实际对照为：

| 事件处理 | 全期净收益 | 最大回撤 |
| --- | --- | --- |
| 当前JEV配置 | +72.6141% | 17.0864% |
| 关闭JEV模块 | −7.5404% | 25.1764% |
| 同样的JEV触发，但关闭方向作用 | +75.5829% | 16.7330% |
| 每条新闻固定暂停，不使用模型评分 | +87.7577% | 16.7320% |

**系统作用已被观察到**：开关事件模块会改变挂单、仓位路径和停机时机，所以它在程序中有实际控制作用。

**模型优于规则的增量尚未被证明**：固定新闻暂停的收益更高；关闭模型方向作用也略好。对照中的收益差包含干预之后的所有持仓变化，不能直接归因为模型准确理解新闻、预测多空或识别危险。当前阈值覆盖大多数新闻，也使它的实际行为接近广泛的消息暂停机制。

模型本身在9月95条事件上准确率约78.95%，简单类别频率基线相同；模型Log loss约0.6813，基线约0.6682，越低越好。故不能以看似较高的准确率来宣称具备交易优势。

## 时效性与风险判断的限制

本地预热后的单条推理约106ms，说明计算可进入秒级链路；实际新闻使用事后获取的出版/修改时间加5秒作为可用时间代理，缺少历史接收日志。消息延迟改成60秒后主方案转为−22.0558%，说明结果对事件时序敏感。手续费加倍且滑点10bp后为−21.5321%。

这些证据支持把JEV保留为可关闭、可比较的研究性事件过滤器。当前不宜让“模型分数”取得绕过硬风控的权限，也没有足够证据把它当成已验证的多空盈利预测器。后续要研究真正的“弃仓判断”，需输入持仓和风险状态，用不同动作的后续结果训练并做独立验证。
